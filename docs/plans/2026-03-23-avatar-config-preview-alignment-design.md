# 头像显示、后台配置对齐与预览一致性设计

## 1. 目标
- 修复头像上传后前台不显示的问题。
- 清理后台中前台无映射的管理项，仅保留前台可见配置。
- 后台文章预览与前台文章渲染链路对齐，减少所见即所得偏差。

## 2. 已确认方案
采用方案 A（低技术债）：
- 统一头像来源：前台多个区域使用同一“当前头像”获取逻辑。
- 统一配置入口：后台保留 `FrontendConfigManager` 作为前台配置入口，移除重复/无映射入口。
- 统一文章渲染：后台预览复用前台文章渲染组件，避免双实现分叉。

## 3. 关键设计
### 3.1 头像链路
- 后端保持 `GET /api/avatars` + `is_current` 约定。
- 前端 `Home`、`Sidebar` 都从头像接口解析当前头像 URL，不再混用 `siteBlock.avatar`。
- 上传行为默认自动设为当前头像（减少额外操作，确保“上传即见”）。

### 3.2 后台菜单与路由对齐
- 保留：`frontend-config / articles / comments / contacts / skills / avatars`。
- 删除重复入口：`content`（与 `frontend-config` 职责重叠）。
- 后台默认首页指向前台配置页，避免“简介管理”与新配置页并存。

### 3.3 文章预览对齐
- 抽取前台 markdown 渲染单元（含 GFM/数学公式/代码块与 Mermaid）。
- 后台 `MarkdownUploadPreview` 直接复用该渲染单元。
- 前台 `ArticleDetail` 同步复用，保证渲染策略一致。

## 4. TDD 与回归范围
- 头像：新增测试覆盖 Sidebar 使用头像接口而非静态字段。
- 后台配置：新增测试覆盖后台不再渲染 `Content` 导航入口。
- 预览：新增测试覆盖后台预览与前台共享同一 markdown 渲染组件。

## 5. 风险控制
- 不改数据库结构，不扩散后端契约。
- 仅在现有组件内复用，不新建平行系统。
- 所有变更先写失败测试，再最小实现。
